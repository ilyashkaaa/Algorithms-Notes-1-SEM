[Определение] Амортизационный анализ (Amortized Analysis)

В традиционном анализе оценивается худшее время выполнения одиночной операции. Однако в структурах данных единичная «тяжелая» операция (например, копирование всего массива) может происходить крайне редко и быть следствием накопления множества дешевых операций.

Амортизированная стоимость (Amortized Cost): Если последовательность из $m$ операций над структурой данных в худшем случае суммарно выполняется за время $T(m)$, то амортизированным временем одной операции называется величина:

$$T_{\mathrm{amort}} = \frac{T(m)}{m}$$
Важное отличие от среднего времени: Амортизированная оценка не является вероятностной. Она гарантирует, что любая конкретная серия из $m$ операций в самом наихудшем сценарии займет суммарно не более $m \cdot T_{\mathrm{amort}}$ времени.
[Метод] Бухгалтерский учет (Метод монеток / Banker's Method)

Каждой элементарной операции присваивается фиктивная учетная стоимость в виртуальных «монетках» (credits):

  • Пусть $c_i$ — реальная стоимость $i$-й операции (1 монета = $O(1)$ элементарных действий).
  • Пусть $\hat{c}_i$ — назначенная нами учетная (амортизированная) стоимость.
  • Если $\hat{c}_i > c_i$, избыток $\hat{c}_i - c_i$ помещается на банковский счет (или привязывается к конкретным элементам структуры как предоплаченный резерв).
  • Если дорогая операция имеет $c_i > \hat{c}_i$, недостающая часть оплачивается накопленными монетами со счета.

Фундаментальный инвариант банка: Баланс счета никогда не должен уходить в минус:

$$\sum_{i=1}^m \hat{c}_i - \sum_{i=1}^m c_i \ge 0 \quad \implies \quad \sum_{i=1}^m c_i \le \sum_{i=1}^m \hat{c}_i$$

Если баланс всегда $\ge 0$, то сумма назначенных учетных стоимостей служит строгой верхней гранью для суммарного реального времени!

[Теорема и Доказательство] Амортизация push_back с удвоением (3 монетки)

Рассмотрим динамический массив (вектор), удваивающий свою вместимость при заполнении: $N \to 2N$.

Теорема (Лекция 5, Кулапин): Амортизированная стоимость операции $\mathrm{push\_back}$ при геометрическом расширении с коэффициентом 2 равна $O(1)$ (ровно 3 монетки).

Доказательство методом монеток:

  1. Пусть запись одного элемента в массив стоит 1 монету, и копирование одного элемента на новое место при реаллокации тоже стоит 1 монету.
  2. За каждую операцию $\mathrm{push\_back}$ будем взимать 3 монетки ($\hat{c} = 3$):
    • 1-я монетка: Непосредственно оплачивает физическую запись нового элемента в ячейку массива.
    • 2-я монетка (депозит): Кладется на сам этот только что вставленный элемент (индекс $i$). Она будет использована в будущем для оплаты его переноса при следующем расширении.
    • 3-я монетка (депозит): Кладется на парный элемент из первой половины массива (индекс $i - N/2$), который уже был скопирован в прошлый раз и остался «без монет».
  3. Инвариант перед реаллокацией: Перед расширением массив был заполнен на $N/2$ элементов. За время добавления второй половины из $N/2$ элементов в массив пришло: $$\frac{N}{2} \times 2 \text{ депозитные монетки} = N \text{ монет}$$ Таким образом, на каждом из $N$ элементов массива лежит ровно по одной монете!
  4. Реаллокация: При заполнении выделяется массив размера $2N$. Чтобы скопировать все $N$ старых элементов на новое место, требуется ровно $N$ операций копирования. Эти операции полностью оплачиваются заготовленными $N$ монетами! Баланс в момент перекопирования становится равным 0, не уходя в минус.
Инвариант сохраняется на каждом цикле удвоения. Следовательно, учетная стоимость $\hat{c} = 3$ покрывает любые затраты, а амортизированное время $\mathrm{push\_back}$ строго равно $O(1)$.
[Анализ] Стратегии изменения емкости: $+C$ против $\times 2$

Почему важно именно геометрическое, а не арифметическое расширение памяти?

1. Арифметическое расширение (capacity += C)

При заполнении выделяется память на константу $C$ больше (например, $+1$ или $+100$). Для вставки $n$ элементов произойдет $n/C$ реаллокаций. Суммарное время копирования:

$$\sum_{k=1}^{n/C} (k \cdot C) = C \cdot \frac{\frac{n}{C} \cdot \left(\frac{n}{C} + 1\right)}{2} = \Theta\left(\frac{n^2}{C}\right) = \Theta(n^2)$$

Амортизированное время одного добавления: $\Theta(n^2) / n = \Theta(n)$ — катастрофически неэффективно!

2. Геометрическое расширение (capacity *= k, k > 1)

Емкость умножается на константу $k > 1$ (обычно $k = 2$, в MSVC $k = 1.5$). Число реаллокаций: $\log_k n$. Суммарное время копирования элементов:

$$\sum_{j=0}^{\log_2 n} 2^j = 2^{\log_2 n + 1} - 1 = 2n - 1 = \Theta(n)$$

Амортизированное время: $\Theta(n) / n = O(1)$.

[Summary] Ключевые тезисы метода монеток
  • Амортизированная стоимость: Гарантированная средняя стоимость операции в худшей серии длины $m$.
  • Баланс монет: Сумма учетных стоимостей обязана мажорировать сумму реальных стоимостей: $\sum \hat{c}_i \ge \sum c_i$.
  • Правило 3 монет для push_back: 1 монета на запись, 1 монета на перенос себя в будущем, 1 монета на перенос элемента из первой половины.
  • Результат: За $N/2$ простых добавлений накапливается ровно $N$ монет, покрывающих перекопирование всего массива размера $N$.
💻 Реализация динамического вектора с амортизированным push_back на Java++ 
class DynamicArray {
    private int[] data;
    private int size;
    private int capacity;

    DynamicArray() {
        this.capacity = 1;
        this.size = 0;
        this.data = new int[capacity];
    }

    // Амортизированная сложность: O(1)
    // Худшая единичная операция: O(n)
    void push_back(int value) {
        if (size == capacity) {
            reallocate(capacity * 2);
        }
        data[size] = value;
        size++;
    }

    private void reallocate(int newCapacity) {
        int[] newData = new int[newCapacity];
        for (int i = 0; i < size; i++) {
            newData[i] = data[i]; // Оплачено заготовленными монетами!
        }
        this.data = newData;
        this.capacity = newCapacity;
    }

    int get(int index) {
        return data[index];
    }

    int getSize() {
        return size;
    }
}
