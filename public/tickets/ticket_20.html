[Структура] Расширение дерева поиска полем size (Order Statistic Tree)

В обычном бинарном дереве поиска нахождение $k$-го по величине элемента требует полного симметричного обхода (in-order) и занимает $O(n)$ времени.

Чтобы выполнять поиск $k$-й порядковой статистики за время высоты дерева $O(h)$ (а на сбалансированных деревьях за $O(\log n)$), каждый узел $x$ снабжается дополнительным полем size:

$$\mathrm{size}(x) = 1 + \mathrm{size}(x.\mathrm{left}) + \mathrm{size}(x.\mathrm{right}), \quad \text{где } \mathrm{size}(\mathrm{null}) = 0$$
Поддержка инварианта размера: Поле size легко пересчитывается при возврате из рекурсии во время операций $\mathrm{Insert}$ и $\mathrm{Erase}$ (а также при поворотах дерева), не ухудшая их асимптотику $O(h)$.
[Алгоритм] Поиск $k$-й порядковой статистики: getKth(x, k)

Пусть требуется найти элемент с порядковым индексом $k$ (0-индексация: $0 \le k < n$). Находясь в узле $x$:

  1. Вычисляем размер левого поддерева: $L = \mathrm{size}(x.\mathrm{left})$. Величина $L$ в точности равна количеству элементов в дереве $x$, которые строго меньше $x.\mathrm{key}$.
  2. Ветвление:
    • Если $k < L$: Искомый элемент строго меньше $x.\mathrm{key}$ и лежит в левом поддереве. Рекурсивно спускаемся влево с тем же $k$: $$\mathrm{getKth}(x.\mathrm{left}, k)$$
    • Если $k == L$: В левом поддереве находится ровно $k$ элементов. Следовательно, сам текущий узел $x$ является искомой $k$-й порядковой статистикой! Возвращаем $x.\mathrm{key}$.
    • Если $k > L$: Искомый элемент строго больше $x.\mathrm{key}$ и лежит в правом поддереве. Мы уже отбросили $L$ элементов левого поддерева и сам узел $x$ (всего $L + 1$ элемент). В правом поддереве нужно искать элемент с относительным индексом $k - L - 1$: $$\mathrm{getKth}(x.\mathrm{right}, k - L - 1)$$

Время работы алгоритма пропорционально длине пути от корня до целевого узла: $O(h)$.

[Алгоритм] Ранг ключа в дереве: Rank(key)

Ранг ключа $\mathrm{Rank}(\mathrm{key})$: Количество элементов в дереве, которые строго меньше заданного значения $\mathrm{key}$ (то есть порядковый номер элемента, если бы он находился в дереве).

Алгоритм вычисления:

  • Начинаем в корне с накапливаемым счетчиком $\mathrm{count} = 0$.
  • Если текущий узел $\mathrm{null}$ — возвращаем $\mathrm{count}$.
  • Если $\mathrm{key} \le x.\mathrm{key}$: искомый ключ не превосходит текущего узла, значит ни $x$, ни его правое поддерево не могут быть меньше $\mathrm{key}$ — просто идем влево ($x = x.\mathrm{left}$).
  • Если $\mathrm{key} > x.\mathrm{key}$: весь левый ребенок и сам узел $x$ гарантированно меньше $\mathrm{key}$. Прибавляем к счетчику $\mathrm{size}(x.\mathrm{left}) + 1$ и идем вправо ($x = x.\mathrm{right}$).

Сложность: ровно один спуск от корня к листу за время $O(h)$.

[Алгоритм] Поиск LowerBound и UpperBound

$\mathrm{LowerBound}(\mathrm{key})$: Поиск наименьшего элемента дерева, большего или равного $\mathrm{key}$ ($\min \{ y \in \mathrm{Tree} \mid y.\mathrm{key} \ge \mathrm{key} \}$).

Пошаговая логика LowerBound:
  1. Храним указатель на лучший найденный кандидат: $\mathrm{ans} = \mathrm{null}$.
  2. Пока текущий узел $x \ne \mathrm{null}$:
    • Если $x.\mathrm{key} \ge \mathrm{key}$: узел $x$ подходит под условие! Запоминаем его: $\mathrm{ans} = x$, но в его левом поддереве могут найтись еще более близкие (меньшие) ключи, которые всё еще $\ge \mathrm{key}$ — идем влево: $x = x.\mathrm{left}$.
    • Если $x.\mathrm{key} < \mathrm{key}$: узел $x$ строго меньше $\mathrm{key}$ (и все его левое поддерево тем более меньше) — кандидатов здесь нет, идем вправо: $x = x.\mathrm{right}$.
  3. Возвращаем сохраненный $\mathrm{ans}$.

Аналогично для $\mathrm{UpperBound}(\mathrm{key})$: ищется строго больший элемент ($x.\mathrm{key} > \mathrm{key}$), логика спусков полностью совпадает с заменой условия на строгое неравенство.

[Summary] Операции расширенного BST
Операция Сложность Требование к структуре Результат
getKth(k) $O(h)$ Поле size в узлах Ключ с порядковым номером $k$
Rank(key) $O(h)$ Поле size в узлах Число элементов строго меньших key
LowerBound(key) $O(h)$ Только ключи (стандартный BST) Минимальный элемент $\ge key$
💻 Реализация Order Statistic Tree и LowerBound на Java++ 
class OrderStatisticBST {
    static class Node {
        int key;
        int size = 1;
        Node left, right;
        Node(int key) { this.key = key; }
    }

    private Node root = null;

    private int sz(Node node) {
        return node == null ? 0 : node.size;
    }

    private void updateSize(Node node) {
        if (node != null) {
            node.size = 1 + sz(node.left) + sz(node.right);
        }
    }

    // Поиск k-й порядковой статистики (0 <= k < n) за O(h)
    int getKth(int k) {
        Node cur = root;
        while (cur != null) {
            int leftSize = sz(cur.left);
            if (k == leftSize) {
                return cur.key;
            } else if (k < leftSize) {
                cur = cur.left;
            } else {
                k -= (leftSize + 1);
                cur = cur.right;
            }
        }
        throw new IndexOutOfBoundsException();
    }

    // Подсчет количества элементов < key за O(h)
    int rank(int key) {
        Node cur = root;
        int count = 0;
        while (cur != null) {
            if (key <= cur.key) {
                cur = cur.left;
            } else {
                count += sz(cur.left) + 1;
                cur = cur.right;
            }
        }
        return count;
    }

    // Поиск наименьшего элемента >= key за O(h)
    Integer lowerBound(int key) {
        Node cur = root;
        Node candidate = null;
        while (cur != null) {
            if (cur.key >= key) {
                candidate = cur; // Подходит, ищем еще меньший слева
                cur = cur.left;
            } else {
                cur = cur.right; // Мал, ищем больше справа
            }
        }
        return candidate == null ? null : candidate.key;
    }
}
