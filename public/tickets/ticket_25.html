[Определения] Задачи диапазонных запросов (Range Queries)

Дан числовой массив $A[0 \dots n-1]$. Поступают запросы, задающие полуинтервалы $[l, r)$ (или отрезки $[l, r]$):

1. RMQ (Range Minimum Query) — минимум на отрезке

$$\mathrm{RMQ}(l, r) = \min_{l \le i \le r} A[i]$$

Задача: эффективно находить наименьший элемент на заданном подотрезке.

2. RSQ (Range Sum Query) — сумма на отрезке

$$\mathrm{RSQ}(l, r) = \sum_{i=l}^r A[i]$$

Задача: находить сумму элементов подотрезка.

[Классификация] Режимы исполнения: Static/Dynamic и Online/Offline
Static (Статическая)

Массив фиксирован раз и навсегда. Элементы не изменяются. Допустим долгий предподсчет (Preprocessing), чтобы запросы обрабатывались мгновенно (например, за $O(1)$).

Dynamic (Динамическая)

Между запросами происходят изменения массива:
• Точечное: $A[i] = x$
• Групповое: $A[i] += x \ \forall i \in [l, r]$.

Online (Интерактивная)

Запросы приходят по одному. Алгоритм обязан выдать ответ на текущий запрос до того, как получит следующий (следующий запрос может зависеть от ответа на предыдущий).

Offline (Пакетная)

Все $q$ запросов известны заранее. Алгоритм имеет право перемешать и отсортировать их (сканирующая прямая, алгоритм Мо, сжатие координат) для ускорения.

[Алгебра] Почему RSQ и RMQ требуют принципиально разных структур?

Возможность быстрого ответа на запрос за $O(1)$ или $O(\log n)$ определяется алгебраическими свойствами операции:

  • Обратимость (Группа): Сложение обратимо ($+ \to -$).
    Благодаря этому для статического RSQ работают префиксные суммы: $$\mathrm{sum}(l, r) = \mathrm{pref}[r] - \mathrm{pref}[l - 1] \implies O(1) \text{ времени и } O(n) \text{ памяти}$$ Но операция взятия минимума $\min(a, b)$ необратима! Если из множества $\{3, 7, 5\}$ убрать 3, зная только минимум 3, восстановить новый минимум невозможно. Поэтому префиксные суммы не применимы для RMQ.
  • Идемпотентность (Idempotency): Операция называется идемпотентной, если повторное применение к тому же элементу не меняет результат: $$x \circ x = x \implies \min(x, x) = x, \quad \gcd(x, x) = x, \quad \mathrm{or}(x, x) = x$$ Идемпотентность позволяет разбивать отрезок на два перекрывающихся блока: $$\min(A \cup B) = \min(\min(A), \min(B))$$ Именно на этом свойстве строится Sparse Table (Разреженная таблица), отвечающая на статический RMQ за строго $O(1)$!
  • Ассоциативность (Полугруппа): $(a \circ b) \circ c = a \circ (b \circ c)$. Не требует ни обратимости, ни идемпотентности. Поддерживается универсальной структурой — Деревом отрезков (Segment Tree) за $O(\log n)$.

[Summary] Ключевой выбор структуры для RMQ и RSQ
  • Статический RSQ: Префиксные суммы ($O(n)$ препроцессинг, $O(1)$ запрос, $O(n)$ память).
  • Статический RMQ: Sparse Table ($O(n \log n)$ препроцессинг, $O(1)$ запрос благодаря идемпотентности $\min(a, a) = a$).
  • Динамический RMQ / RSQ с точечным или групповым обновлением: Дерево отрезков ($O(n)$ построение, $O(\log n)$ запрос и обновление).
  • Динамический массив с изменением порядка элементов: Декартово дерево по неявному ключу.
💻 Статический RSQ через префиксные суммы на Java++ 
class StaticRSQ {
    private long[] pref;

    // Построение префиксных сумм за O(n)
    StaticRSQ(int[] a) {
        pref = new long[a.length + 1];
        for (int i = 0; i < a.length; i++) {
            pref[i + 1] = pref[i] + a[i];
        }
    }

    // Запрос суммы на отрезке [l, r] за O(1)
    long query(int l, int r) {
        return pref[r + 1] - pref[l];
    }
}
