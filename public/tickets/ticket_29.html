[Концепция] Что такое неявный ключ (Implicit Key)?

В классическом декартовом дереве (Билет 22) каждый узел хранит явный ключ $x$ (BST) и приоритет $y$ (Heap). Однако если мы моделируем динамический массив, элементам соответствуют их порядковые позиции (индексы $0, 1, \dots, n-1$).

Проблема явных индексов: Если хранить индекс как явный ключ $x$, то при вставке или вырезании элемента в позиции $i$ индексы всех последующих $n - i$ элементов увеличиваются или уменьшаются на 1, что требует $O(n)$ времени на обновление всего дерева.

Идея неявного ключа: Ключ $x$ вообще не хранится в узле! Ключом узла является его порядковый номер в порядке симметричного обхода (in-order traversal) всего дерева.

Позиция узла $v$ внутри его собственного поддерева в 0-индексации строго равна числу узлов в его левом поддереве:

$$\mathrm{index\_in\_subtree}(v) = \mathrm{size}(v.\mathrm{left})$$
Благодаря этому вставка или удаление узла меняет размеры поддеревьев только у его непосредственных предков ($O(\log n)$ узлов), автоматически сдвигая неявные индексы всех элементов правее без физической перезаписи!
[Алгоритмы] Операции Split и Merge по неявному ключу

1. Разрезание: $\mathrm{Split}(T, k) \to (T_1, T_2)$

Разделяет дерево $T$ на $T_1$ (первые $k$ элементов массива) и $T_2$ (оставшиеся $n - k$ элементов):

  1. Если $T == \mathrm{null}$, возвращаем $(\mathrm{null}, \mathrm{null})$.
  2. Обязательно вызываем $\mathrm{push}(T)$ перед спуском в детей.
  3. Считаем размер левого поддерева: $L = \mathrm{size}(T.\mathrm{left})$.
  4. Если $k \le L$: граница разреза находится в левом поддереве:
    Рекурсивно вызываем $(T_1, T_2') = \mathrm{Split}(T.\mathrm{left}, k)$.
    Привязываем: $T.\mathrm{left} = T_2'$, обновляем размер $\mathrm{update}(T)$, возвращаем $(T_1, T)$.
  5. Если $k > L$: граница разреза находится в правом поддереве:
    Рекурсивно вызываем $(T_1', T_2) = \mathrm{Split}(T.\mathrm{right}, k - L - 1)$ (относительный индекс!).
    Привязываем: $T.\mathrm{right} = T_1'$, обновляем размер $\mathrm{update}(T)$, возвращаем $(T, T_2)$.

2. Слияние: $\mathrm{Merge}(T_1, T_2) \to T$

Склеивает массив $T_1$ и массив $T_2$ (все элементы $T_1$ chronologically предшествуют элементам $T_2$):

  • Если одно из деревьев пусто — возвращаем второе.
  • Вызываем $\mathrm{push}(T_1)$ и $\mathrm{push}(T_2)$.
  • Сравниваем приоритеты кучи:
    Если $T_1.y > T_2.y$, то $T_1$ становится корнем: $T_1.\mathrm{right} = \mathrm{Merge}(T_1.\mathrm{right}, T_2)$, $\mathrm{update}(T_1)$, return $T_1$.
    Иначе $T_2$ становится корнем: $T_2.\mathrm{left} = \mathrm{Merge}(T_1, T_2.\mathrm{left})$, $\mathrm{update}(T_2)$, return $T_2$.

Время работы $\mathrm{Split}$ и $\mathrm{Merge}$: строго $O(\log n)$ в среднем благодаря свойствам декартова дерева.

[Задача] Разворот подотрезка массива за $O(\log n)$

Постановка задачи: Дан массив $A[0 \dots n-1]$. Поступают запросы $\mathrm{reverse}(l, r)$, требующие перевернуть порядок следования элементов на отрезке $[l, r]$:

$$A[l] \leftrightarrow A[r], \quad A[l+1] \leftrightarrow A[r-1], \quad \dots$$

Алгоритм решения через Treap по неявному ключу:

  1. Вырезаем подотрезок $[l, r]$ из общего дерева $T$ с помощью двух операций $\mathrm{Split}$:
    • $\mathrm{Split}(T, r + 1) \implies (T_{12}, T_3)$, где $T_3$ — суффикс с индексами $> r$.
    • $\mathrm{Split}(T_{12}, l) \implies (T_1, T_2)$, где $T_1$ — префикс с индексами $< l$.
    В результате дерево $T_2$ содержит в точности элементы отрезка $[l, r]$!
  2. Разворот поддерева $T_2$: вместо физической перестановки всех узлов мы просто инвертируем отложенный флаг в корне: $$T_2.\mathrm{reversed} = T_2.\mathrm{reversed} \oplus \mathrm{true}$$
  3. Склеиваем деревья обратно в исходном порядке: $$T = \mathrm{Merge}(\mathrm{Merge}(T_1, T_2), T_3)$$
Вся операция разворота состоит из 2 вызовов $\mathrm{Split}$, одной битовой операции в корне и 2 вызовов $\mathrm{Merge}$. Сложность: строго $O(\log n)$!
[Алгоритм] Ленивое проталкивание разворота: push(node)

Что означает разворот массива на языке дерева?

При симметричном обходе $\mathrm{in-order}$ посещаются сначала левое поддерево, потом корень, потом правое поддерево: $\mathrm{Left} \to \mathrm{Root} \to \mathrm{Right}$. Чтобы элементы шли в обратном порядке, необходимо, чтобы обход происходил в порядке $\mathrm{Right} \to \mathrm{Root} \to \mathrm{Left}$. Для этого достаточно для каждого узла поддерева поменять местами его левого и правого сыновей:

$$\mathrm{swap}(v.\mathrm{left}, v.\mathrm{right})$$
Функция $\mathrm{push}(v)$:
  1. Если $v == \mathrm{null}$ или $v.\mathrm{reversed} == \mathrm{false}$ — выход.
  2. Флаг поднят: меняем местами ссылки на детей: $$\mathrm{swap}(v.\mathrm{left}, v.\mathrm{right})$$
  3. Передаем флаг детям (инвертируем их флаги):
    if (v.left != null) v.left.reversed ^= true;
    if (v.right != null) v.right.reversed ^= true;
  4. Сбрасываем флаг в текущем узле: $v.\mathrm{reversed} = \mathrm{false}$.

Инвариант: $\mathrm{push}(v)$ вызывается перед любым обращением к детям узла (в начале $\mathrm{Split}$, $\mathrm{Merge}$, $\mathrm{print}$ и т.д.), гарантируя актуальность связей.

💻 Реализация Implicit Treap с операцией Reverse подотрезка на Java++ 
class ImplicitTreap {
    static class Node {
        int val;
        int y; // Случайный приоритет кучи
        int size = 1;
        boolean reversed = false; // Отложенный флаг разворота
        Node left, right;

        Node(int val) {
            this.val = val;
            this.y = rnd.nextInt();
        }
    }

    private static final Random rnd = new Random();
    private Node root = null;

    private int sz(Node t) { return t == null ? 0 : t.size; }

    private void update(Node t) {
        if (t != null) {
            t.size = 1 + sz(t.left) + sz(t.right);
        }
    }

    // Проталкивание отложенного бита разворота за O(1)
    private void push(Node t) {
        if (t != null && t.reversed) {
            Node tmp = t.left; t.left = t.right; t.right = tmp; // swap(left, right)
            if (t.left != null) t.left.reversed ^= true;
            if (t.right != null) t.right.reversed ^= true;
            t.reversed = false;
        }
    }

    // Слияние двух подмассивов за O(log n)
    private Node merge(Node t1, Node t2) {
        push(t1);
        push(t2);
        if (t1 == null) return t2;
        if (t2 == null) return t1;

        if (t1.y > t2.y) {
            t1.right = merge(t1.right, t2);
            update(t1);
            return t1;
        } else {
            t2.left = merge(t1, t2.left);
            update(t2);
            return t2;
        }
    }

    // Разрезание на первые k элементов и остальные за O(log n)
    private Node[] split(Node t, int k) {
        if (t == null) return new Node[] { null, null };
        push(t);
        int leftSize = sz(t.left);

        if (k <= leftSize) {
            Node[] res = split(t.left, k);
            t.left = res[1];
            update(t);
            return new Node[] { res[0], t };
        } else {
            Node[] res = split(t.right, k - leftSize - 1);
            t.right = res[0];
            update(t);
            return new Node[] { t, res[1] };
        }
    }

    // Разворот подотрезка [l, r] за O(log n)
    void reverse(int l, int r) {
        Node[] p1 = split(root, r + 1);   // p1[0] = [0..r], p1[1] = [r+1..n-1]
        Node[] p2 = split(p1[0], l);       // p2[0] = [0..l-1], p2[1] = [l..r]

        if (p2[1] != null) {
            p2[1].reversed ^= true;         // Отложенный разворот целевого подотрезка!
        }

        root = merge(merge(p2[0], p2[1]), p1[1]);
    }
}
