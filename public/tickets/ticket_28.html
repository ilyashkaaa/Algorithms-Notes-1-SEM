[Концепция] Запрос группового обновления и лень (Lazy Propagation)

Групповое обновление (Range Update): Применить операцию изменения $ch(\cdot, val)$ ко всем элементам на отрезке $[l, r]$. Например:

$$A[i] = A[i] + val \quad \forall i \in [l, r]$$

Проблема наивного обновления: Если обновлять каждый лист индивидуально, операция займет $O((r - l + 1) \log n) = O(n \log n)$.

Идея отложенной модификации (Lazy Propagation): Если отрезок узла $[tl, tr]$ целиком содержится внутри отрезка обновления $[l, r]$, не нужно рекурсивно спускаться в его потомков! Мы запоминаем «обещание» обновить поддерево в виде отложенной пометки (несогласованности) $lazy[v]$, сразу пересчитываем агрегат текущего узла $tree[v]$ и завершаем вызов.

[Алгебра] Три условия совместности операций (Лекция 8, Кулапин)

Пусть $op$ — операция запроса на отрезке (например, $\min$), а $ch$ — операция модификации (например, $+ val$). Для корректной работы Lazy Propagation операция $ch$ обязана удовлетворять трем аксиомам:

  1. Существование нейтрального элемента $e_{ch}$: $$ch(x, e_{ch}) = x \quad (\text{например, } +0 \text{ при прибавлении})$$
  2. Ассоциативность модификаций: $$ch(a, ch(b, c)) = ch(ch(a, b), c)$$ Позволяет накапливать последовательные обновления в узле: если к узлу последовательно применили $val_1$, затем $val_2$, новая отложенная пометка равна $ch(lazy[v], val_2)$.
  3. Дистрибутивность модификации относительно операции запроса $op$: $$ch(op(a, b), c) = op(ch(a, c), ch(b, c))$$ Пример для RMQ и прибавления: $\min(a + c, b + c) = \min(a, b) + c$. Благодаря этому значению узла $\min$ можно сразу прибавить $c$ без пересчета сыновей!
    Пример для RSQ и прибавления: $\sum_{i=1}^k (a_i + c) = \sum a_i + k \cdot c$.
[Алгоритм] Проталкивание несогласованности (push)

Несогласованность (Lazy Tag): Величина $lazy[v]$, хранящаяся в узле, которую необходимо передать детям, чтобы значения в их поддеревьях стали истинными.

Процедура $\mathrm{push}(v, tl, tr)$: Вызывается перед тем, как спуститься в детей узла $v$:

  1. Если узел является листом ($tl == tr$) или пометка нейтральна ($lazy[v] == e_{ch}$) — делать ничего не нужно.
  2. Применяем пометку $lazy[v]$ к левому ребенку $2v+1$:
    $\mathrm{apply}(2v+1, lazy[v])$;
  3. Применяем пометку $lazy[v]$ к правому ребенку $2v+2$:
    $\mathrm{apply}(2v+2, lazy[v])$;
  4. Сбрасываем пометку в текущем узле: $lazy[v] = e_{ch}$.
Функция $\mathrm{push}$ работает за строго $O(1)$ и восстанавливает согласованность перед любым разделением отрезка.
[Алгоритмы] Обновление отрезка и Запрос за $O(\log n)$

1. Групповое обновление: $\mathrm{updateRange}(v, tl, tr, l, r, val)$

  1. Если отрезок узла не пересекается с $[l, r]$ ($l > tr$ или $r < tl$) — выход.
  2. Если отрезок узла целиком внутри запроса ($l \le tl \le tr \le r$):
    Применяем модификацию: $\mathrm{apply}(v, val)$, и немедленно выходим! ($O(1)$).
  3. Частичное пересечение:
    • Вызываем $\mathrm{push}(v, tl, tr)$.
    • Рекурсивно обновляем детей: левого и правого.
    • Пересчитываем значение текущего узла: $$\mathrm{tree}[v] = \mathrm{tree}[2v+1] \circ \mathrm{tree}[2v+2]$$

2. Запрос на отрезке: $\mathrm{query}(v, tl, tr, l, r)$

  1. Не пересекается $\implies$ возвращаем $\mathrm{neutral}$.
  2. Целиком внутри $\implies$ возвращаем $\mathrm{tree}[v]$ за $O(1)$.
  3. Частичное пересечение:
    • Обязательно вызываем $\mathrm{push}(v, tl, tr)$!
    • Возвращаем объединение ответов от левого и правого сыновей: $$\mathrm{ans} = \mathrm{query}(2v+1, \dots) \circ \mathrm{query}(2v+2, \dots)$$

Точечное обновление: Является тривиальным частным случаем $\mathrm{updateRange}(pos, pos, val)$ и выполняется за то же время $O(\log n)$.

[Summary] Сводные параметры дерева отрезков с Lazy Propagation
Операция Сложность Механика
Build $O(n)$ Инициализация tree и зануление lazy
Range Update $O(\log n)$ Покрытие отрезка не более чем $2 \log n$ узлами с пометками
Range Query $O(\log n)$ Спуск с проталкиванием push на каждом шаге
Память $2 \times 4n = 8n$ Массивы tree[4n] и lazy[4n]
💻 Дерево отрезков на минимум с прибавлением на отрезке на Java++ 
class LazySegmentTreeRMQ {
    private int[] tree;
    private int[] lazy;
    private int n;
    private static final int INF = Integer.MAX_VALUE;

    LazySegmentTreeRMQ(int[] a) {
        this.n = a.length;
        this.tree = new int[4 * n];
        this.lazy = new int[4 * n];
        build(a, 0, 0, n - 1);
    }

    private void build(int[] a, int v, int tl, int tr) {
        if (tl == tr) { tree[v] = a[tl]; return; }
        int tm = (tl + tr) / 2;
        build(a, 2 * v + 1, tl, tm);
        build(a, 2 * v + 2, tm + 1, tr);
        tree[v] = Math.min(tree[2 * v + 1], tree[2 * v + 2]);
    }

    // Применение модификации к узлу
    private void apply(int v, int val) {
        tree[v] += val;
        lazy[v] += val;
    }

    // Проталкивание пометки в детей за O(1)
    private void push(int v) {
        if (lazy[v] != 0) {
            apply(2 * v + 1, lazy[v]);
            apply(2 * v + 2, lazy[v]);
            lazy[v] = 0;
        }
    }

    // Групповое прибавление val на [l, r] за O(log n)
    void updateRange(int l, int r, int val) {
        updateRec(0, 0, n - 1, l, r, val);
    }

    private void updateRec(int v, int tl, int tr, int l, int r, int val) {
        if (l > tr || r < tl) return;
        if (l <= tl && tr <= r) {
            apply(v, val);
            return;
        }
        push(v);
        int tm = (tl + tr) / 2;
        updateRec(2 * v + 1, tl, tm, l, r, val);
        updateRec(2 * v + 2, tm + 1, tr, l, r, val);
        tree[v] = Math.min(tree[2 * v + 1], tree[2 * v + 2]);
    }

    // Запрос минимума на [l, r] за O(log n)
    int query(int l, int r) {
        return queryRec(0, 0, n - 1, l, r);
    }

    private int queryRec(int v, int tl, int tr, int l, int r) {
        if (l > tr || r < tl) return INF;
        if (l <= tl && tr <= r) return tree[v];
        push(v);
        int tm = (tl + tr) / 2;
        return Math.min(
            queryRec(2 * v + 1, tl, tm, l, r),
            queryRec(2 * v + 2, tm + 1, tr, l, r)
        );
    }
}
