[Определение] Splay-дерево

Splay-дерево — самобалансирующееся двоичное дерево поиска, которое не хранит никаких дополнительных метаданных в узлах (ни высот, как в AVL, ни приоритетов, как в Treap, ни цветов, как в RB-Tree).

Фундаментальный принцип: После каждого обращения к вершине $x$ (поиск, вставка, удаление) вызывается операция $\mathrm{Splay}(x)$, которая поднимает вершину $x$ в корень дерева с помощью цепочки специальных поворотов.

В худшем случае дерево может временно вырождаться в бамбук высоты $\Theta(n)$, а одиночная операция может стоить $\Theta(n)$. Однако операция $\mathrm{Splay}$ при подъеме «складывает» и укорачивает длинные ветви дерева вдвое, гарантируя амортизированную сложность $O(\log n)$ для любой последовательности операций!
[Алгоритм] 3 типа шагов операции Splay(x)

Пусть $p$ — родитель узла $x$, а $g$ — родитель $p$ (дедушка $x$). Подъем $x$ в корень состоит из последовательности шагов трех типов:

1. Шаг zig (одиночный поворот)

Применяется, когда родитель $p$ уже является корнем дерева ($g = \mathrm{null}$). Выполняется ровно один поворот ребра $(x, p)$ (правый или левый). Применяется не более одного раза в самом конце процедуры $\mathrm{Splay}$, если исходная глубина $x$ была нечетной.

2. Шаг zig-zig (однонаправленный двойной поворот)

Применяется, когда $x$ и $p$ лежат по одну сторону: либо оба левые дети ($x = p.\mathrm{left}$ и $p = g.\mathrm{left}$), либо оба правые.

Критический порядок поворотов: Сначала поворачиваем $p$ вокруг дедушки $g$, и только затем $x$ вокруг $p$!
Почему это критично: Именно такой порядок располовинивает длину пути от $g$ до корня, превращая вырожденный бамбук в сбалансированное дерево. Если наивно повернуть сначала $x$, а потом $p$, длина ветви не уменьшится.

3. Шаг zig-zag (разнонаправленный двойной поворот)

Применяется, когда $x$ и $p$ лежат по разные стороны: например, $x$ — правый сын $p$, а $p$ — левый сын $g$ (зигзаг). Сначала поворачиваем $x$ вокруг $p$, а затем $x$ вокруг $g$ (аналог большого поворота в AVL).

[Анализ] Функция потенциала и понятие ранга

Для амортизированного анализа вводится:

  • $s(v)$ — размер поддерева с корнем в вершине $v$ (число узлов в нем).
  • Ранг вершины $r(v)$: логарифм размера ее поддерева: $$r(v) = \log_2 s(v)$$
  • Функция потенциала всего дерева $\Phi(T)$: сумма рангов всех его вершин: $$\Phi(T) = \sum_{v \in T} r(v) = \sum_{v \in T} \log_2 s(v)$$

При поворотах узлов размеры и ранги меняются только у вершин $x, p, g$, участвующих в повороте. Ранги всех остальных узлов дерева остаются неизменными.

[Теорема и Доказательство] Теорема о времени работы операции Splay

Теорема о времени работы Splay: Учетная стоимость операции $\mathrm{Splay}(x)$ в дереве с корнем $t$ ограничена величиной:

$$\hat{C}_{\mathrm{Splay}} \le 3(r(t) - r(x)) + 1 \le 3 \log_2 n + 1 = O(\log n)$$

Доказательство леммы по шагам (Лекция 7, Кулапин): Пусть $r(u)$ и $r'(u)$ — ранги вершины $u$ до и после шага соответственно.

  • Оценка шага zig (1 поворот): Реальное время $= 1$. Меняются ранги только $x$ и $p$, причем $r'(x) = r(p)$ и $r'(p) < r'(x)$: $$\hat{c} = 1 + (r'(x) + r'(p) - r(x) - r(p)) \le 1 + r'(x) - r(x) \le 1 + 3(r'(x) - r(x))$$
  • Оценка шага zig-zig (2 поворота): Реальное время $= 2$. Заметим, что $r'(x) = r(g)$. Используя вогнутость логарифма ($\log a + \log b \le 2 \log \frac{a+b}{2}$), для непересекающихся поддеревьев $r(x) + r'(g) \le 2r'(x) - 2$. Отсюда учетная стоимость: $$\hat{c} = 2 + r'(x) + r'(p) + r'(g) - r(x) - r(p) - r(g) \le 3(r'(x) - r(x))$$
  • Оценка шага zig-zag (2 поворота): Аналогично через вогнутость логарифма: $$\hat{c} \le 2(r'(x) - r(x)) \le 3(r'(x) - r(x))$$

Телескопическое суммирование: Просуммируем учетные стоимости всех шагов от листа $x$ до корня $t$:

$$\hat{C}_{\mathrm{total}} = \sum \hat{c}_i \le 1 + \sum 3(r_{i}(x) - r_{i-1}(x)) = 1 + 3(r_{\mathrm{root}}(x) - r_{\mathrm{start}}(x))$$

Так как $r_{\mathrm{root}}(x) = \log_2 n$, а $r_{\mathrm{start}}(x) \ge 0$:

$$\hat{C}_{\mathrm{total}} \le 3 \log_2 n + 1 = O(\log n)$$
Вывод: Амортизированное время работы операции $\mathrm{Splay}(x)$ строго составляет $O(\log n)$.
[Summary] Сводные тезисы Splay
  • Память на узел: 0 байт метаданных (только `left`, `right`, `parent`).
  • Худшее время одной операции: $O(n)$, но амортизированное — $O(\log n)$.
  • Порядок zig-zig: Сначала родитель $p$ вокруг дедушки $g$, потом $x$ вокруг $p$.
  • Потенциал: $\Phi = \sum_{v} \log_2 s(v)$.
  • Свойство самоадаптации: Часто запрашиваемые элементы находятся около корня, обеспечивая доступ за $O(1)$ (статическая и динамическая оптимальность).
💻 Реализация процедуры Splay (zig, zig-zig, zig-zag) на Java++ 
class SplayTreeBase {
    static class Node {
        int key;
        Node left, right, parent;
        Node(int key) { this.key = key; }
    }

    Node root = null;

    private void rotate(Node x) {
        Node p = x.parent;
        Node g = p.parent;
        boolean isLeft = (x == p.left);

        if (isLeft) {
            p.left = x.right;
            if (x.right != null) x.right.parent = p;
            x.right = p;
        } else {
            p.right = x.left;
            if (x.left != null) x.left.parent = p;
            x.left = p;
        }
        p.parent = x;
        x.parent = g;
        if (g != null) {
            if (p == g.left) g.left = x;
            else g.right = x;
        } else {
            root = x;
        }
    }

    // Подъем вершины x в корень: амортизированно O(log n)
    void splay(Node x) {
        if (x == null) return;
        while (x.parent != null) {
            Node p = x.parent;
            Node g = p.parent;
            if (g == null) {
                // Шаг zig
                rotate(x);
            } else if ((x == p.left) == (p == g.left)) {
                // Шаг zig-zig: сначала родитель p, затем x!
                rotate(p);
                rotate(x);
            } else {
                // Шаг zig-zag: дважды поворачиваем x
                rotate(x);
                rotate(x);
            }
        }
    }
}
