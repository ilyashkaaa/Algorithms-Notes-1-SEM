[Определение] Задача сортировки в модели сравнений

Постановка задачи сортировки: Дан массив элементов $A = [a_1, a_2, \dots, a_n]$. Требуется найти такую перестановку индексов $\pi \in S_n$, для которой элементы упорядочены по неубыванию: $$a_{\pi(1)} \le a_{\pi(2)} \le \dots \le a_{\pi(n)}$$

Модель сортировок на сравнениях: Алгоритм может получать информацию о взаимном расположении элементов исключительно с помощью бинарной операции сравнения: $$\text{«Правда ли, что } x < y \text{ (или } x \le y \text{)?»}$$ Алгоритм не знает внутренней структуры элементов (их битового представления, диапазона значений) и не может использовать элементы в качестве индексов массива.

[Определение] Дерево решений (Decision Tree)

Работу любого алгоритма сортировки на сравнениях для фиксированного размера входа $n$ можно представить в виде дерева решений (двоичного дерева):

  1. Внутренние вершины: Каждая нелистовая вершина помечена сравнением двух элементов $a_i \le a_j$.
  2. Ребра: Из каждой внутренней вершины выходят ровно два ребра: левое соответствует исходу $a_i \le a_j$ ($\mathrm{yes}$), правое — $a_i > a_j$ ($\mathrm{no}$).
  3. Листья: Каждый лист помечен перестановкой $\pi$, задающей итоговый отсортированный порядок элементов.
  4. Высота дерева $h$: Длина самого длинного пути от корня до листа соответствует максимальному числу сравнений в худшем случае.
[Теорема] Нижняя граница времени сортировки сравнениями

Любой детерминированный или рандомизированный алгоритм сортировки $n$ элементов, основанный исключительно на сравнениях, в худшем случае требует не менее $\Omega(n \log n)$ операций сравнения:

$$T(n) = \Omega(n \log n)$$
[Доказательство] Через число листьев дерева решений

Шаг 1 (Число листьев): Всего существует $n!$ возможных перестановок из $n$ различных элементов. Чтобы алгоритм корректно сортировал любой входной массив, каждая из $n!$ перестановок должна присутствовать хотя бы в одном достижимом листе дерева решений (иначе для некоторого входа алгоритм не сможет выдать правильный ответ). Пусть $L$ — число листьев дерева решений. Тогда: $$L \ge n!$$

Шаг 2 (Ограничение через высоту): В двоичном дереве высоты $h$ число листьев не превосходит $2^h$: $$L \le 2^h$$

Шаг 3 (Логарифмирование): $$2^h \ge L \ge n! \implies h \ge \log_2(n!)$$

Шаг 4 (Оценка $\log_2(n!)$ снизу): $$\log_2(n!) = \sum_{i=1}^n \log_2 i \ge \sum_{i=\lceil n/2 \rceil}^n \log_2 i \ge \sum_{i=\lceil n/2 \rceil}^n \log_2\left(\frac{n}{2}\right) = \frac{n}{2} (\log_2 n - 1) = \frac{n}{2} \log_2 n - \frac{n}{2}$$ Следовательно, $h \ge \frac{1}{2} n \log_2 n - O(n) = \Omega(n \log n)$.

Так как число сравнений в худшем случае равно высоте дерева $h$, то $T(n) \ge h = \Omega(n \log n)$. $\blacksquare$

[Определение] Стабильная (устойчивая) сортировка

Сортировка называется стабильной (stable), если она сохраняет относительный порядок следования элементов с одинаковыми ключами:

$$i < j \quad \text{и} \quad \mathrm{key}(a_i) == \mathrm{key}(a_j) \implies \text{в отсортированном массиве элемент } a_i \text{ предшествует } a_j$$

Зачем нужна стабильность?

  • Многоуровневая сортировка: Например, отсортировать список студентов сначала по фамилии, а затем по номеру группы. Если сортировка по группе стабильна, то внутри каждой группы студенты останутся отсортированы по фамилии!
  • Основа поразрядной сортировки (LSD Radix Sort): Алгоритм сортирует числа по разрядам от младшего к старшему. Корректность опирается исключительно на стабильность каждого прохода.

Классификация алгоритмов:

  • Стабильные: Merge Sort (при $\le$), Insertion Sort, Bubble Sort, Counting Sort (с префиксными суммами и проходом справа налево).
  • Нестабильные: QuickSort (далекие `swap` через пивот), HeapSort (переброска корня в конец массива), Selection Sort.

★ Summary билета (ключевые факты)
  • Как обойти барьер $\Omega(n \log n)$?
    Нижняя граница $\Omega(n \log n)$ доказана только для моделей сравнений! Несравнивающие алгоритмы (Counting Sort, Radix Sort, Bucket Sort) используют числовое значение элементов как индекс в массиве и работают за линейное время $O(n + k)$.
  • Сводная таблица алгоритмов:
    Алгоритм Худшее время Среднее время Память Стабильность
    Merge Sort $O(n \log n)$ $O(n \log n)$ $O(n)$ Стабильна
    QuickSort $O(n^2)$ $O(n \log n)$ $O(\log n)$ стек Нестабильна
    HeapSort $O(n \log n)$ $O(n \log n)$ $O(1)$ на месте Нестабильна
    Counting Sort $O(n + k)$ $O(n + k)$ $O(k)$ Стабильна

class Item {
    int key;
    String tag;
    Item(int key, String tag) { this.key = key; this.tag = tag; }
}
