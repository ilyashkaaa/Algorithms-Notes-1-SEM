[Определение] Односвязный и двусвязный списки

Связный список — динамическая структура данных, состоящая из узлов (Nodes), каждый из которых содержит полезную нагрузку и указатели на соседние узлы в динамической памяти.

1. Односвязный список (Singly Linked List)

Узел содержит поле val и один указатель next.

  • Вставка и удаление из головы (head): строго $O(1)$.
  • Вставка/удаление после известного узла: $O(1)$.
  • Доступ по порядковому номеру $k$: $\Theta(k) = O(n)$ последовательным проходом.
  • Удаление узла по указателю на него: $O(n)$, так как необходимо найти предшествующий узел для переподвешивания указателя next.

2. Двусвязный список (Doubly Linked List)

Узел содержит val, next и prev.

  • Вставка и удаление в оба конца (head и tail): строго $O(1)$.
  • Удаление любого известного узла за строго $O(1)$ без поиска: node.prev.next = node.next; node.next.prev = node.prev;
  • Минусы: Расход памяти (2 указателя на каждый элемент = 16 байт оверхеда на 64-битных ОС) и плохая локальность данных в кэше процессора (cache misses).
[Концепции] Последовательные контейнеры: Стек, Очередь, Дек
  • Стек (Stack, LIFO — Last In, First Out): Доступен только последний добавленный элемент.
    Реализация: на динамическом массиве (вершина в конце, $O(1)$ аморт.) или на односвязном списке (вершина в голове, строго $O(1)$ худшего времени).
  • Очередь (Queue, FIFO — First In, First Out): Добавление в конец (`push`), извлечение из начала (`pop`).
    Реализация: на односвязном списке с указателями на `head` и `tail` (строго $O(1)$) или на кольцевом буфере.
  • Дек (Deque — Double-Ended Queue): Двусторонняя очередь, поддерживающая добавление и удаление с обоих концов за $O(1)$.
    Реализация: на двусвязном списке или на динамическом кольцевом буфере.
[Структура] Кольцевой буфер (Ring Buffer)

Кольцевой буфер (циклический буфер) — массив фиксированного размера $C$, логически закольцованный с помощью двух индексов: head (начало очереди) и tail (место вставки следующего элемента).

Инварианты и арифметика по модулю $C$:

$$\mathrm{push}(x): \quad A[\mathrm{tail}] = x, \quad \mathrm{tail} = (\mathrm{tail} + 1) \bmod C, \quad \mathrm{size}++$$ $$\mathrm{pop}(): \quad x = A[\mathrm{head}], \quad \mathrm{head} = (\mathrm{head} + 1) \bmod C, \quad \mathrm{size}--$$
  • Преимущество: Память переиспользуется по кругу без выделения новых узлов в куче и без сдвига элементов массива: операции занимают строго $O(1)$ худшего времени!
  • Контейнер std::deque в C++: Реализован как массив указателей на непрерывные блоки фиксированного размера (chunk ring buffer), что обеспечивает доступ по произвольному индексу за $O(1)$, вставку в оба конца за $O(1)$ и отсутствие инвалидации указателей на не удаляемые элементы при расширении.
🔄 Кольцевой буфер (Ring Buffer) емкости $C = 8$

[1] • empty
[2] A head

Зацикливание без сдвигов памяти: при переходе через правый край (индекс $C-1 \to 0$) указатель автоматически возвращается в начало за строго $O(1)$ худшего времени без единой реаллокации.
[Алгоритм] Очередь на двух стеках с поддержкой ассоциативной операции

Задача: Реализовать очередь, поддерживающую добавление $\mathrm{push}(x)$, удаление $\mathrm{pop}()$ и вычисление результата произвольной операции над всеми элементами очереди $\mathrm{query}() = x_1 \circ x_2 \circ \dots \circ x_k$ за амортизированное $O(1)$.

1. Вспомогательный примитив: Стек с поддержкой операции

В каждом узле стека храним пару $(\mathrm{val}, \mathrm{agg})$, где $\mathrm{agg}$ — накопленный результат операции от дна стека до текущего элемента:

$$\mathrm{push}(x): \quad \mathrm{agg}_{\mathrm{new}} = \begin{cases} x, & \text{если стек пуст} \\ \mathrm{stack.top().agg} \circ x, & \text{иначе} \end{cases}$$

Значение операции на всем стеке доступно в вершине за строго $O(1)$: $\mathrm{query}_{\mathrm{stack}} = \mathrm{stack.top().agg}$.

2. Двухстековая очередь

Заводим два стека с поддержкой операции: stack_in (входной) и stack_out (выходной):

  • $\mathrm{push}(x)$: Всегда добавляем элемент в stack_in. Время $O(1)$.
  • $\mathrm{pop}()$:
    • Если stack_out не пуст, просто извлекаем вершину из stack_out.
    • Если stack_out пуст, последовательно извлекаем все элементы из stack_in и помещаем их в stack_out (порядок элементов естественным образом разворачивается в правильный FIFO!). Затем извлекаем вершину stack_out.
  • $\mathrm{query}()$:
    • Если пуст stack_in: возвращаем $\mathrm{stack\_out.query()}$.
    • Если пуст stack_out: возвращаем $\mathrm{stack\_in.query()}$.
    • Если оба не пусты: объединяем их агрегаты в правильном хронологическом порядке: $$\mathrm{result} = \mathrm{stack\_out.query()} \circ \mathrm{stack\_in.query()}$$
Амортизированный анализ: Каждый элемент попадает в stack_in (1 операция), единожды перекладывается в stack_out (1 операция) и один раз удаляется из stack_out (1 операция). Итого ровно 3 операции на элемент, поэтому амортизированная стоимость всех операций $\mathrm{push}$, $\mathrm{pop}$ и $\mathrm{query}$ равна $O(1)$!
⚡ Очередь на двух стеках с поддержкой ассоциативной операции $\mathrm{query}()$
📥 stack_in (Входной стек)
$\mathrm{push}(x)$ всегда сюда за $O(1)$
val: 1 agg: $a_1$
val: 2 agg: $a_1 \circ a_2$
val: 3 (top) agg: $a_1 \circ a_2 \circ a_3$
⇄
Перекладывание
Срабатывает только при пустом stack_out. Порядок элементов разворачивается!
$\mathrm{query}() = \mathrm{out.agg} \circ \mathrm{in.agg}$
📤 stack_out (Выходной стек)
$\mathrm{pop}()$ всегда отсюда (FIFO!)
val: 3 agg: $a_3$
val: 2 agg: $a_2 \circ a_3$
val: 1 (top) agg: $a_1 \circ a_2 \circ a_3$
Амортизированный анализ: каждый элемент 1 раз добавляется в stack_in, ровно 1 раз переливается в stack_out и 1 раз извлекается через $\mathrm{pop}()$. Суммарно 3 операции на элемент $\implies$ амортизированное $O(1)$ на операцию!
[Алгебра] Какие требования накладываются на операцию?

Ассоциативность — обязательное и достаточное условие:

$$(a \circ b) \circ c = a \circ (b \circ c)$$

Очередь на двух стеках вычисляет:

$$\underbrace{(x_1 \circ \dots \circ x_k)}_{\text{агрегат в stack\_out}} \circ \underbrace{(x_{k+1} \circ \dots \circ x_m)}_{\text{агрегат в stack\_in}}$$

Благодаря ассоциативности расстановка скобок не меняет результат вычисления.

  • Коммутативность НЕ требуется: Порядок элементов строго сохраняется ($\mathrm{stack\_out}$ идет chronologically раньше $\mathrm{stack\_in}$). Можно поддерживать перемножение матриц!
  • Обратимость НЕ требуется: В отличие от префиксных сумм, где для удаления элемента требовалось вычитание (обратный элемент), очередь на двух стеках работает с полугруппами: поиск минимума $\min(a, b)$, максимума $\max(a, b)$, наибольшего общего делителя $\gcd(a, b)$!

💻 Очередь с поддержкой минимума / ассоциативной операции на Java++ 
class MinQueue {
    static class StackNode {
        int val;
        int minUnder;
        StackNode(int val, int minUnder) {
            this.val = val;
            this.minUnder = minUnder;
        }
    }

    private ArrayList<StackNode> stackIn = new ArrayList<>();
    private ArrayList<StackNode> stackOut = new ArrayList<>();

    // Добавление элемента: O(1)
    void push(int x) {
        int curMin = stackIn.isEmpty() ? x : Math.min(x, stackIn.get(stackIn.size() - 1).minUnder);
        stackIn.add(new StackNode(x, curMin));
    }

    // Удаление элемента: амортизированно O(1)
    int pop() {
        if (stackOut.isEmpty()) {
            while (!stackIn.isEmpty()) {
                int val = stackIn.remove(stackIn.size() - 1).val;
                int curMin = stackOut.isEmpty() ? val : Math.min(val, stackOut.get(stackOut.size() - 1).minUnder);
                stackOut.add(new StackNode(val, curMin));
            }
        }
        return stackOut.remove(stackOut.size() - 1).val;
    }

    // Запрос ассоциативной операции (минимума) за строго O(1)
    int getMin() {
        if (stackIn.isEmpty()) {
            return stackOut.get(stackOut.size() - 1).minUnder;
        }
        if (stackOut.isEmpty()) {
            return stackIn.get(stackIn.size() - 1).minUnder;
        }
        return Math.min(
            stackIn.get(stackIn.size() - 1).minUnder,
            stackOut.get(stackOut.size() - 1).minUnder
        );
    }
}
