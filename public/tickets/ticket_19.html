[Определение] Бинарное дерево поиска (Binary Search Tree)

Бинарное дерево поиска (BST) — это двоичное дерево, в каждом узле $x$ которого хранится ключ $x.\mathrm{key}$, удовлетворяющее инварианту BST:

$$\forall u \in \mathrm{left}(x) \implies u.\mathrm{key} \le x.\mathrm{key}$$ $$\forall v \in \mathrm{right}(x) \implies v.\mathrm{key} > x.\mathrm{key}$$

(В модели с уникальными ключами в левом поддереве строго меньшие элементы, в правом — строго большие).

Симметричный обход (In-order traversal): Рекурсивный обход поддеревьев в порядке $\mathrm{Left} \to \mathrm{Node} \to \mathrm{Right}$ посещает ключи дерева в строго неубывающем отсортированном порядке за линейное время $\Theta(n)$.

[Алгоритмы] Базовые операции Find и Insert за $O(h)$

1. Поиск: $\mathrm{Find}(x, \mathrm{key})$

Сравниваем искомый $\mathrm{key}$ с ключом текущего узла:

  • Если текущий узел $\mathrm{null}$ — ключ отсутствует в дереве ($\mathrm{false}$).
  • Если $\mathrm{key} == x.\mathrm{key}$ — элемент найден ($\mathrm{true}$).
  • Если $\mathrm{key} < x.\mathrm{key}$ — идем влево: $x = x.\mathrm{left}$.
  • Если $\mathrm{key} > x.\mathrm{key}$ — идем вправо: $x = x.\mathrm{right}$.

2. Вставка: $\mathrm{Insert}(x, \mathrm{key})$

Идем вниз по дереву аналогично поиску $\mathrm{Find}$:

  • Если встречаем узел с совпадающим ключом — завершаем работу (ключ уже есть).
  • Как только путь поиска пытается перейти в отсутствующий узел ($\mathrm{null}$), создаем новый узел с данным ключом и привязываем его к родителю.
[Алгоритм] Удаление узла Erase(key) (Лекционный разбор 3 случаев)

Сначала находим узел $z$, содержащий удаляемый ключ. Если такой узел отсутствует — дерево не меняется. Если найден, возможны 3 случая в зависимости от числа сыновей узла $z$:

Случай 1: Узел $z$ — лист (0 детей)

Узел просто удаляется из дерева, а соответствующий указатель у его родителя ($z.\mathrm{parent}$) зануляется.

Случай 2: Узел $z$ имеет ровно одного ребенка

Единственный сын узла $z$ (левый или правый) переподвешивается напрямую к родителю $z$, занимая место $z$. Сам узел $z$ освобождается.

Случай 3: Многодетный узел (2 ребенка)

Узел $z$ имеет обоих детей. Нельзя просто вырезать его без нарушения структуры:

  1. Найдем наименьший элемент, строго больший $z.\mathrm{key}$ — это следующий элемент в порядке симметричного обхода (in-order successor) $y$.
  2. Для поиска $y$ делаем один шаг вправо ($z.\mathrm{right}$), а затем спускаемся влево до упора ($y = \mathrm{findMin}(z.\mathrm{right})$).
  3. Ключевое свойство $y$: Узел $y$ гарантированно не имеет левого ребенка! (иначе мы могли бы спуститься еще левее).
  4. Копируем значение $y.\mathrm{key}$ в узел $z$.
  5. Удаляем исходный узел $y$ из правого поддерева: так как у $y$ не более одного ребенка, это сводится к тривиальному Случаю 1 или Случаю 2!
[Теорема] Временная сложность и проблема вырождения в бамбук

Все три операции ($\mathrm{Find}$, $\mathrm{Insert}$, $\mathrm{Erase}$) на каждом шаге спускаются строго на один уровень вниз по дереву.

Следовательно, время работы любой операции составляет:

$$T(n) = O(h)$$

где $h$ — высота дерева (длина максимального пути от корня до листа).

Проблема наивного BST:
  • Лучший случай: Идеально сбалансированное дерево: $h = \lfloor \log_2 n \rfloor \implies O(\log n)$.
  • Худший случай: Если ключи поступают в отсортированном порядке ($1, 2, 3, \dots, n$), каждый следующий элемент подвешивается правым сыном предыдущего. Дерево вырождается в связный список (бамбук) глубины $h = n$, а операции деградируют до $O(n)$!
Для предотвращения вырождения используются самобалансирующиеся деревья поиска (AVL, Treap, Splay, RB-Tree).
[Summary] Сводные свойства бинарного дерева поиска
Операция Средняя сложность Худшая сложность (бамбук) Суть действий
Find(key) $O(\log n)$ $O(n)$ Спуск влево или вправо по ключу
Insert(key) $O(\log n)$ $O(n)$ Поиск листа и прикрепление нового узла
Erase(key) $O(\log n)$ $O(n)$ 3 случая (замена на in-order successor)
💻 Реализация BST (Find, Insert, Erase) на Java++ 
class BinarySearchTree {
    static class Node {
        int key;
        Node left, right;
        Node(int key) { this.key = key; }
    }

    private Node root = null;

    // Поиск ключа: O(h)
    boolean find(int key) {
        Node cur = root;
        while (cur != null) {
            if (key == cur.key) return true;
            cur = (key < cur.key) ? cur.left : cur.right;
        }
        return false;
    }

    // Вставка ключа: O(h)
    void insert(int key) {
        root = insertRec(root, key);
    }

    private Node insertRec(Node node, int key) {
        if (node == null) return new Node(key);
        if (key < node.key) {
            node.left = insertRec(node.left, key);
        } else if (key > node.key) {
            node.right = insertRec(node.right, key);
        }
        return node;
    }

    // Удаление ключа: O(h) с разбором 3 случаев
    void erase(int key) {
        root = eraseRec(root, key);
    }

    private Node eraseRec(Node node, int key) {
        if (node == null) return null;

        if (key < node.key) {
            node.left = eraseRec(node.left, key);
        } else if (key > node.key) {
            node.right = eraseRec(node.right, key);
        } else {
            // Найден удаляемый узел!
            // Случай 1 и 2: 0 или 1 ребенок
            if (node.left == null) return node.right;
            if (node.right == null) return node.left;

            // Случай 3: 2 ребенка. Ищем in-order successor (минимум в правом поддереве)
            Node succ = findMin(node.right);
            node.key = succ.key; // Заменяем ключ
            node.right = eraseRec(node.right, succ.key); // Удаляем преемника
        }
        return node;
    }

    private Node findMin(Node node) {
        while (node.left != null) node = node.left;
        return node;
    }
}
