[Определение] Дерево отрезков (Segment Tree)

Дерево отрезков — двоичное дерево, каждый узел которого отвечает за некоторый подотрезок массива $[tl, tr]$.

  • Корень дерева отвечает за весь диапазон массива $[0, n - 1]$.
  • Узел с диапазоном $[tl, tr]$ при $tl < tr$ имеет двух детей:
    • Левый сын отвечает за первую половину: $[tl, tm]$, где $tm = \lfloor (tl + tr) / 2 \rfloor$.
    • Правый сын отвечает за вторую половину: $[tm + 1, tr]$.
  • Листья дерева ($tl == tr$) соответствуют одиночным элементам исходного массива $A[tl]$.
Алгебраическая область применимости: Любая ассоциативная операция $\circ$ с нейтральным элементом $e$ (алгебраический моноид): $$(a \circ b) \circ c = a \circ (b \circ c), \quad a \circ e = e \circ a = a$$ Не требуется ни коммутативности (можно перемножать матрицы), ни обратимости (можно искать минимум $\min$, максимум $\max$, $\gcd$), ни идемпотентности!
[Алгоритм] Массивное представление, оценка памяти $4n$ и построение $O(n)$

Дерево отрезков размещается в одном плоском массиве tree[] с 0-индексацией:

$$\mathrm{root} = 0, \quad \mathrm{left}(v) = 2v + 1, \quad \mathrm{right}(v) = 2v + 2$$

Оценка размера массива: ровно $4n$

Если длина массива $n$ является точной степенью двойки ($n = 2^k$), то дерево является идеальным полным двоичным деревом: в нем $n$ листьев и $n - 1$ внутренних узлов, итого $2n - 1 < 2n$ ячеек. Если $n$ не является степенью двойки, дополним $n$ до ближайшей степени двойки $2^{\lceil \log_2 n \rceil} < 2n$. Дерево над таким массивом потребует не более $2 \cdot (2n) = 4n$ ячеек. Массива размера $4n$ гарантированно хватает без динамических аллокаций.

Построение снизу вверх за $O(n)$:

Функция $\mathrm{build}(v, tl, tr)$:

  • Если $tl == tr$ (лист): $\mathrm{tree}[v] = A[tl]$.
  • Иначе: строим детей $\mathrm{build}(2v+1, tl, tm)$ и $\mathrm{build}(2v+2, tm+1, tr)$, после чего объединяем их агрегаты: $$\mathrm{tree}[v] = \mathrm{tree}[2v + 1] \circ \mathrm{tree}[2v + 2]$$

Так как каждый узел посещается один раз за $O(1)$, а число узлов $< 4n$, время построения строго равно $O(n)$.

[Алгоритм] Точечное изменение за $O(\log n)$

Запрос: обновить значение в ячейке $A[\mathrm{pos}] = \mathrm{new\_val}$.

  1. Спускаемся от корня вниз к листу с индексом $\mathrm{pos}$. На каждом шаге переходим либо только в левого ребенка (если $\mathrm{pos} \le tm$), либо только в правого (если $\mathrm{pos} > tm$).
  2. В листе ($tl == tr == \mathrm{pos}$) обновляем значение: $\mathrm{tree}[v] = \mathrm{new\_val}$.
  3. При возврате из рекурсии снизу вверх пересчитываем значение в каждом предке вдоль пути спуска: $$\mathrm{tree}[v] = \mathrm{tree}[2v + 1] \circ \mathrm{tree}[2v + 2]$$

Глубина дерева равна $\lceil \log_2 n \rceil$. На каждом уровне обрабатывается ровно 1 узел. Время точечного обновления: $O(\log n)$.

[Алгоритм и Теорема] Ответ на запрос на отрезке за $O(\log n)$

Функция $\mathrm{query}(v, tl, tr, l, r)$ для отрезка запроса $[l, r]$:

  1. Случай 1 (Нет пересечения): $l > tr$ или $r < tl$. Диапазон узла лежит полностью вне запроса — возвращаем нейтральный элемент $\mathrm{neutral}$ ($+\infty$ для минимума, $0$ для суммы).
  2. Случай 2 (Полное включение): $l \le tl \le tr \le r$. Диапазон узла целиком покрыт запросом — сразу возвращаем предподсчитанное значение $\mathrm{tree}[v]$ за $O(1)$!
  3. Случай 3 (Частичное пересечение): Делим запрос серединой $tm$ и рекурсивно обращаемся к обоим сыновьям: $$\mathrm{ans} = \mathrm{query}(2v+1, tl, tm, l, r) \circ \mathrm{query}(2v+2, tm+1, tr, l, r)$$
Доказательство сложности $O(\log n)$: На любом фиксированном уровне дерева отрезков отрезок запроса $[l, r]$ может частично пересекать (вызывая ветвление) не более двух узлов: один узел, содержащий левую границу $l$, и один узел, содержащий правую границу $r$. Все узлы между ними попадут в Случай 2 (полное включение) и мгновенно вернут ответ без спуска в детей. Следовательно, на каждом из $O(\log n)$ уровней обрабатывается не более 4 узлов. Суммарное число операций строго равно $O(\log n)$.
[Summary] Базовое дерево отрезков
Операция Временная сложность Суть
Build $O(n)$ Рекурсивная инициализация снизу вверх
Point Update $O(\log n)$ Спуск в лист и пересчет вдоль одной ветви
Range Query $O(\log n)$ Разбиение отрезка не более чем на $2 \log n$ блоков
Память $4n$ ячеек Один линейный массив без указателей
💻 Реализация дерева отрезков на минимум (RMQ) на Java++ 
class SegmentTree {
    private int[] tree;
    private int n;
    private static final int INF = Integer.MAX_VALUE;

    SegmentTree(int[] a) {
        this.n = a.length;
        this.tree = new int[4 * n];
        build(a, 0, 0, n - 1);
    }

    // Построение дерева за O(n)
    private void build(int[] a, int v, int tl, int tr) {
        if (tl == tr) {
            tree[v] = a[tl];
            return;
        }
        int tm = (tl + tr) / 2;
        build(a, 2 * v + 1, tl, tm);
        build(a, 2 * v + 2, tm + 1, tr);
        tree[v] = Math.min(tree[2 * v + 1], tree[2 * v + 2]);
    }

    // Точечное обновление A[pos] = val за O(log n)
    void update(int pos, int val) {
        updateRec(0, 0, n - 1, pos, val);
    }

    private void updateRec(int v, int tl, int tr, int pos, int val) {
        if (tl == tr) {
            tree[v] = val;
            return;
        }
        int tm = (tl + tr) / 2;
        if (pos <= tm) {
            updateRec(2 * v + 1, tl, tm, pos, val);
        } else {
            updateRec(2 * v + 2, tm + 1, tr, pos, val);
        }
        tree[v] = Math.min(tree[2 * v + 1], tree[2 * v + 2]);
    }

    // Запрос минимума на [l, r] за O(log n)
    int query(int l, int r) {
        return queryRec(0, 0, n - 1, l, r);
    }

    private int queryRec(int v, int tl, int tr, int l, int r) {
        if (l > tr || r < tl) return INF;
        if (l <= tl && tr <= r) return tree[v];
        int tm = (tl + tr) / 2;
        return Math.min(
            queryRec(2 * v + 1, tl, tm, l, r),
            queryRec(2 * v + 2, tm + 1, tr, l, r)
        );
    }
}
