[Определение] Быстрая сортировка (Divide and Conquer)

Быстрая сортировка (Quick Sort) — рекурсивный алгоритм сортировки, использующий парадигму «Разделяй и властвуй».

Базовая схема алгоритма для отрезка $[l, r]$:

  1. База рекурсии: Если $l \ge r$, отрезок пуст или состоит из одного элемента — он уже отсортирован, завершаем работу.
  2. Выбор опорного элемента (Pivot): Выбирается некоторый элемент $p$ массива (случайно, медиана из трех, крайний или центральный).
  3. Partition (Разбиение): Элементы массива на отрезке $[l, r]$ переставляются на месте ($O(1)$ доп. памяти) так, что все элементы, меньшие $p$, оказываются слева, а большие — справа.
  4. Рекурсивный шаг: Алгоритм рекурсивно вызывается для сформированных подмассивов слева и справа от опорного элемента.
[Алгоритмы] Процедуры Partition с $O(1)$ дополнительной памяти

Ключевой шаг QuickSort — переставить элементы на месте без выделения вспомогательного массива размера $O(n)$ (в отличие от MergeSort).

1. Двусторонняя схема с двумя указателями — классический вариант лекции

Два указателя $i = l$ и $j = r$ двигаются навстречу друг другу:

  • Указатель $i$ сдвигается вправо, пока $A[i] < p$.
  • Указатель $j$ сдвигается влево, пока $A[j] > p$.
  • Если $i \le j$, элементы $A[i]$ и $A[j]$ нарушают порядок относительно $p$ — меняем их местами ($\mathrm{swap}(A[i], A[j])$), сдвигаем $i{++}, j{--}$.
  • Процесс повторяется, пока $i \le j$. В итоге возвращается пара индексов $\{j, i\}$, разбивающих массив на две части: левую $[l, j]$ и правую $[i, r]$.
Плюсы двусторонней схемы: Совершает в среднем в 3 раза меньше операций обмена ($\mathrm{swap}$), чем схема Ломуто, и отлично работает на массивах с повторяющимися элементами, не допуская вырождения в $O(n^2)$.

2. Схема Ломуто (Lomuto Partition)

Опорный элемент помещается в конец: $p = A[r]$. Указатель $i = l - 1$ отслеживает границу элементов $< p$. Бегущий указатель $j$ проходит от $l$ до $r-1$:

  • Если $A[j] \le p$, то увеличиваем $i$ и делаем $\mathrm{swap}(A[i], A[j])$.
  • В конце ставим опорный на границу: $\mathrm{swap}(A[i+1], A[r])$, и возвращаем индекс $i+1$.

Недостаток Ломуто: Если все элементы массива одинаковы, условие $A[j] \le p$ выполняется всегда, $i$ доходит до конца, и массив делится на размер $n-1$ и $0$, приводя к времени $O(n^2)$.

3. Трехчастное разбиение (3-Way Partitioning / Флаг Нидерландов)

Делит массив на три зоны: элементы строго меньше $p$ ($[l \dots lt-1]$), равные $p$ ($[lt \dots gt]$) и строго больше $p$ ($[gt+1 \dots r]$). Рекурсивные вызовы происходят только для интервалов $[l, lt-1]$ и $[gt+1, r]$. Это гарантирует время $O(n)$ на массиве с одинаковыми элементами.

[Теорема] Временная сложность Quick Sort

Время работы зависит от сбалансированности разбиения, определяемой выбором опорного элемента $\mathrm{pivot}$.

1. Худший случай: $O(n^2)$

Возникает, когда на каждом шаге выбранный пивот оказывается минимальным или максимальным элементом (например, при фиксированном выборе первого/последнего элемента в уже отсортированном или обратно отсортированном массиве).

$$T(n) = T(n - 1) + T(0) + \Theta(n) = \sum_{k=1}^n \Theta(k) = \Theta(n^2)$$

2. Несбалансированное, но фиксированное деление ($p : q$)

Утверждение (из лекции): Пусть удается выбирать пивот так, что он делит отрезок в пропорции не хуже чем $p : q$, где $p + q = 1$, $p, q > 0$ (например, $1/10$ и $9/10$). Тогда худшее время работы составляет $O(n \log n)$.

Идея доказательства: Рассмотрим дерево рекурсии. Длина самой длинной ветви ограничена глубиной $\log_{1/q}(n) = O(\log n)$. На каждом уровне дерева рекурсии суммарно обрабатывается не более $n$ элементов, то есть суммарная работа на уровне равна $O(n)$. Следовательно, суммарное время:

$$T(n) \le O(n) \cdot \log_{1/q}(n) = O(n \log n)$$

3. Среднее время работы со случайным пивотом (Randomized QuickSort)

Теорема: При случайном равновероятном выборе опорного элемента $\mathrm{pivot} \in [l, r]$ математическое ожидание времени работы алгоритма Quick Sort составляет:

$$\mathbb{E}[T(n)] = \Theta(n \log n)$$

Интуиция: С вероятностью $1/2$ случайный элемент попадает в интервал между 25-м и 75-м процентилями, давая разбиение не хуже $1:3$. В среднем через каждые 2 вызова отрезок делится константно, обеспечивая ожидаемую логарифмическую глубину.

[Анализ] Затраты памяти стека и Tail Call Optimization

Дополнительная память самого массива равна $O(1)$. Однако вызовы функции сохраняются в стеке вызовов (call stack):

  • Наивная реализация: В худшем случае при перекосе $1$ и $n-1$ глубина рекурсии достигает $O(n)$, что приводит к переполнению стека (Stack Overflow).
  • Оптимизация хвостовой рекурсии (Tail Recursion Elimination):

    Сначала рекурсивно вызываем QuickSort от меньшей из двух частей, а для большей части заменяем вызов циклом (сдвигая границу $l$ или $r$).

Гарантия памяти: Так как рекурсия вызывается только для подмассива размером не более $\lfloor n/2 \rfloor$, глубина стека гарантированно не превышает $\lfloor \log_2 n \rfloor$. Следовательно, дополнительная память по стеку всегда составляет $O(\log n)$ даже при худшем сценарии разбиения!

💻 Реализация QuickSort (Двусторонняя схема + Random Pivot + Tail Call Opt) на Java++ 
class QuickSortAlgorithm {
    private Random rnd = new Random();

    // Процедура разбиения с двумя указателями (лекционный вариант)
    // Возвращает пару граничных индексов [j, i], делящих отрезок на [l, j] и [i, r]
    int[] partitionTwoPointers(int[] a, int l, int r) {
        int pivotIdx = l + rnd.nextInt(r - l + 1);
        int pivot = a[pivotIdx];

        int i = l;
        int j = r;

        while (i <= j) {
            while (a[i] < pivot) { i++; }
            while (a[j] > pivot) { j--; }

            if (i >= j) {
                break;
            }
            swap(a, i, j);
            i++;
            j--;
        }
        return new int[] { j, i };
    }

    // Быстрая сортировка с оптимизацией хвостовой рекурсии (стек O(log n))
    void quickSort(int[] a, int l, int r) {
        while (l < r) {
            int[] boundary = partitionTwoPointers(a, l, r);
            int j = boundary[0];
            int i = boundary[1];

            // Рекурсивно идем в строго меньшую половину
            if (j - l < r - i) {
                quickSort(a, l, j);
                l = i; // Большую обрабатываем в цикле
            } else {
                quickSort(a, i, r);
                r = j; // Большую обрабатываем в цикле
            }
        }
    }

    void swap(int[] a, int i, int j) {
        int tmp = a[i]; a[i] = a[j]; a[j] = tmp;
    }
}
