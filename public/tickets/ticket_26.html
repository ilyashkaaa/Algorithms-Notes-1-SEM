[Применимость] Область применимости Sparse Table

Разреженная таблица (Sparse Table) предназначена для обслуживания диапазонных запросов на статических массивах (где элементы никогда не меняются).

Ключевые алгебраические условия:

  • Ассоциативность операции $\circ$: $(a \circ b) \circ c = a \circ (b \circ c)$. Необходима для корректности объединения блоков.
  • Идемпотентность операции $\circ$ ($x \circ x = x$): Позволяет отвечать на запрос за строго $O(1)$! Примеры: $$\min(x, x) = x \ (\mathrm{RMQ}), \quad \max(x, x) = x, \quad \gcd(x, x) = x, \quad (x \mid x) = x \ (\mathrm{bit\ OR})$$
Почему массив обязан быть статическим: При точечной модификации элемента $A[i]$ необходимо пересчитать все покрывающие его блоки на всех уровнях. На уровне $k$ это $2^k$ ячеек, суммарно $\sum_{k=0}^{\log n} 2^k = O(n)$ времени на обновление! Поэтому любая динамика разрушает эффективность таблицы.
[Алгоритм] Построение Sparse Table через ДП за $O(n \log n)$

Определим двумерный массив $st[k][i]$ как результат операции на отрезке длины $2^k$, начинающемся в индексе $i$:

$$st[k][i] = \bigoplus_{j = i}^{i + 2^k - 1} A[j] \quad (\text{где } i + 2^k \le n)$$

Динамическое программирование по степеням двойки:

  • База ДП ($k = 0$): Блоки длины $2^0 = 1$ — это сами элементы массива: $$st[0][i] = A[i] \quad \forall i \in [0, n - 1]$$
  • Переход ДП ($k - 1 \to k$): Блок длины $2^k$ разбивается на два соседних блока вдвое меньшей длины $2^{k-1}$: $$st[k][i] = st[k - 1][i] \circ st[k - 1][i + 2^{k - 1}]$$

Сложность построения и память: Число уровней $K = \lfloor \log_2 n \rfloor + 1$. На каждом уровне вычисляется не более $n$ ячеек за константное время $O(1)$. Итого время построения: $O(n \log n)$, память: $O(n \log n)$.

[Алгоритм и Теорема] Ответ на идемпотентный запрос за $O(1)$

Пусть требуется вычислить $\mathrm{RMQ}(l, r)$ на отрезке $[l, r]$ длины $\mathrm{len} = r - l + 1$.

  1. Находим максимальную степень двойки $k$, не превосходящую длину отрезка: $$k = \lfloor \log_2(\mathrm{len}) \rfloor = \lfloor \log_2(r - l + 1) \rfloor$$ Свойство: $2^k \le \mathrm{len} < 2^{k+1}$.
  2. Берем два перекрывающихся блока длины $2^k$:
    • Левый блок: начинается в $l$ $\implies [l, l + 2^k - 1] \implies st[k][l]$.
    • Правый блок: заканчивается в $r$ $\implies [r - 2^k + 1, r] \implies st[k][r - 2^k + 1]$.
  3. Так как $2^k > \mathrm{len} / 2$, эти два блока полностью покрывают весь отрезок $[l, r]$!
  4. Идемпотентность устраняет дублирование: Элементы на пересечении блоков учитываются дважды, но в силу идемпотентности $\min(A \cup B) = \min(\min(A), \min(B))$: $$\mathrm{ans} = \min\left(st[k][l], \ st[k][r - 2^k + 1]\right)$$
Время ответа: Вычисление $k$ занимает $O(1)$ (через предпосчитанную таблицу логарифмов или битовую операцию 31 - numberOfLeadingZeros(len)), обращение к двум ячейкам таблицы — $O(1)$. Итого ответ на запрос за строго $O(1)$!
[Обобщение] Что делать, если операция не идемпотентна (например, сумма)?

Для неидемпотентных операций (сложение, умножение матриц) перекрытие недопустимо: элементы на пересечении войдут в сумму повторно!

Решение через бинарное разложение: Длина любого отрезка $\mathrm{len}$ представляется суммой степеней двойки (своими единичными битами в двоичной записи): $$\mathrm{len} = 2^{k_1} + 2^{k_2} + \dots + 2^{k_m}, \quad m \le \log_2 n$$ Отрезок разбивается на $m$ непересекающихся блоков, которые последовательно объединяются слева направо.

Время ответа составит $O(\log n)$. Однако для статических сумм гораздо эффективнее использовать префиксные суммы ($O(1)$ запрос и $O(n)$ память), а для динамических ассоциативных операций — дерево отрезков.

[Summary] Сводные параметры Sparse Table
Характеристика Значение Комментарий
Время построения $O(n \log n)$ $\log n$ слоев по $n$ элементов через ДП
Память $O(n \log n)$ Таблица размера $[\log n + 1][n]$
Время RMQ (минимум/максимум/GCD) $O(1)$ Два перекрывающихся блока длины $2^k$
Поддержка модификаций Нет ($O(n)$) Строго статический массив
💻 Реализация Sparse Table для RMQ на Java++ ($O(1)$ запрос) 
class SparseTableRMQ {
    private int[][] st;
    private int[] lg;

    SparseTableRMQ(int[] a) {
        int n = a.length;
        // Предподсчет логарифмов за O(n)
        lg = new int[n + 1];
        lg[1] = 0;
        for (int i = 2; i <= n; i++) {
            lg[i] = lg[i / 2] + 1;
        }

        int maxLog = lg[n] + 1;
        st = new int[maxLog][n];

        // База ДП: блоки длины 2^0 = 1
        for (int i = 0; i < n; i++) {
            st[0][i] = a[i];
        }

        // Переход ДП: объединение двух блоков размера 2^(k-1)
        for (int k = 1; k < maxLog; k++) {
            int len = 1 << (k - 1);
            for (int i = 0; i + (1 << k) <= n; i++) {
                st[k][i] = Math.min(st[k - 1][i], st[k - 1][i + len]);
            }
        }
    }

    // Запрос минимума на отрезке [l, r] за строго O(1)
    int queryMin(int l, int r) {
        int len = r - l + 1;
        int k = lg[len];
        return Math.min(st[k][l], st[k][r - (1 << k) + 1]);
    }
}
